# Notes Events

Плагин для Obsidian к сервису [notificator](https://github.com/zotochev/notes), который создаёт
события Google Calendar и задачи Google Tasks из блоков `<event>` и `<task>` в заметках.

Плагин показывает такие блоки панелями вместо XML и даёт форму, чтобы создавать и менять их, не
редактируя теги руками. Формат файлов остаётся тем же: сервис читает их как раньше.

Работает в Obsidian для компьютера, версии 1.5.0 и новее.

## Установка

### Вручную

1. Скачайте `main.js`, `manifest.json` и `styles.css` со страницы
   [последнего релиза](https://github.com/zotochev/notes-obsidian-plugin/releases/latest)
   (или архив `notes-events.zip` с этими тремя файлами).
2. В папке хранилища создайте папку `.obsidian/plugins/notes-events` и положите файлы в неё.
   Папка `.obsidian` скрытая.
3. В Obsidian откройте «Настройки» → «Сторонние плагины». Если включён ограниченный режим,
   отключите его.
4. Обновите список установленных плагинов и включите «Notes Events».

Чтобы обновить плагин, замените три файла новыми и выключите и включите плагин в настройках.

### Через BRAT

[BRAT](https://github.com/TfTHacker/obsidian42-brat) ставит плагины прямо из репозитория и сам
обновляет их.

1. Установите и включите BRAT из каталога сторонних плагинов.
2. В палитре команд выполните «BRAT: Add a beta plugin for testing».
3. Укажите адрес `https://github.com/zotochev/notes-obsidian-plugin`.
4. Включите «Notes Events» в настройках сторонних плагинов.

## Как пользоваться

### Создать событие или задачу

Поставьте курсор туда, где должен быть блок, и сделайте одно из двух:

- нажмите правую кнопку мыши и выберите «Вставить событие» или «Вставить задачу»;
- откройте палитру команд (`Ctrl+P`) и выберите «Notes Events: Вставить событие» или
  «Notes Events: Вставить задачу».

Заполните форму и нажмите «Сохранить». Идентификатор `uid` подставляется сам.

Командам можно назначить горячие клавиши: «Настройки» → «Горячие клавиши», поиск «Notes Events».

Команды доступны в режиме редактирования. В режиме чтения блоки можно менять, но не создавать.

### Изменить или удалить

Нажмите на панель: откроется та же форма. В ней есть кнопки «Удалить» и «XML» — последняя
показывает блок текстом и даёт править его напрямую.

Редкие поля — участники, календарь или список задач, часовой пояс — находятся под
«Ещё поля». Там же выключатель: выключенный блок остаётся в заметке, но сервис его не видит.

### uid

По `uid` сервис находит запись в Google, поэтому плагин создаёт его сам — из даты и времени,
например `20260407111400`, — и следит, чтобы в файле он не повторялся. Он показан под
«Ещё поля». Если блок скопировали вместе с `uid`, оба блока покажут ошибку: откройте копию и
нажмите «Новый uid».

Менять `uid` обычно не нужно. Если всё же нужно, нажмите «Изменить» рядом с ним. С другим `uid`
сервис удалит прежнюю запись в Google и создаст новую; то же произойдёт, если поменять `uid`
руками в тексте заметки.

### Даты

Дату можно выбрать в календаре или ввести текстом, как её понимает сервис: «завтра в 10:00»,
«через 3 дня». Между способами переключает кнопка справа от поля. Дату, записанную текстом,
плагин не трогает, пока вы сами её не измените.

У события без конца длительность 30 минут. У задачи хранится только дата срока, без времени.

### Ошибки

Плагин проверяет блок по тем же правилам, что и сервис. Блок с ошибкой показывается красной
панелью с объяснением, а форма не даёт сохранить блок с ошибкой. Дату, записанную текстом,
плагин не проверяет: её разбирает сервис.

## Вид панели

У панели два вида: строка (компактный) и карточка (с местом, участниками и описанием). Вид и
цвет выбираются в форме для каждого блока. Вид для блоков, у которых он не выбран, задаётся в
настройках плагина.

В режиме Source mode панели не показываются: там виден исходный текст.

## Что записывается в файл

Блок записывается в блок кода `xml`, чтобы заметка нормально читалась и там, где плагина нет:

````
```xml
<event>
  <!-- view: card; color: purple -->
  <uid>a7kq2m9x</uid>
  <summary>Планёрка</summary>
  <start>2026-11-18 10:00</start>
  <end>2026-11-18 10:30</end>
</event>
```
````

- Вид и цвет хранятся в комментарии `<!-- view: …; color: … -->` внутри блока. `view` — `row` или
  `card`; `color` — `blue`, `green`, `purple`, `red`, `orange`, `yellow`, `pink` или `cyan`.
  Сервис комментарий пропускает.
- Выключенный блок — это `#` перед открывающим тегом: `#<event>`.
- Блоки, написанные раньше без блока кода, тоже показываются панелями и получают блок кода при
  первом сохранении через форму. Команда «Обернуть все события и задачи заметки в блоки кода»
  делает это сразу для всей заметки.
- Блок, у которого на той же строке есть другой текст, остаётся без блока кода.
- При сохранении теги блока записываются в одном порядке и с одними отступами. Теги и
  комментарии, которых плагин не знает, сохраняются.

Описание полей — в [README сервиса](https://github.com/zotochev/notes#readme).

## Разработка

```bash
npm install
npm test         # тесты разбора и записи блоков
npm run build    # проверка типов и сборка main.js
npm run dev      # пересборка при изменениях
```

Для релиза нужны `main.js`, `manifest.json` и `styles.css`. Тег релиза должен совпадать с
`version` в `manifest.json`, без буквы `v`.
